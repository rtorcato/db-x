# Examples

The canonical DB-X example is [`examples/dbx/postgres`](https://github.com/rtorcato/infra-x/tree/main/examples/dbx/postgres)
in the monorepo — a runnable project that applies the **same** Postgres schema
two ways.

:::warning Experimental
DB-X is an early prototype. Do not point it at a database you care about.
:::

## `examples/dbx/postgres` — one schema, two runtimes

The schema (a `todos` table) is imported from `@db-x/postgres-library`. Two
entry files apply it through different runtime parents:

| File | Runtime parent | CLI | Use case |
| --- | --- | --- | --- |
| [`dbx.tsx`](https://github.com/rtorcato/infra-x/tree/main/examples/dbx/postgres/dbx.tsx) | `<DatabaseTarget url={...}>` | `db-x` | Production — points at an existing managed DB via a `postgres://` URL. |
| [`infra.tsx`](https://github.com/rtorcato/infra-x/tree/main/examples/dbx/postgres/infra.tsx) | `<Service image="postgres:16-alpine">` | `infra-x` | Local dev / CI — stands the DB up via Compose, then runs the schema against it. |

Only the runtime parent differs — that's what proves DB-X composes with the
broader Infra-X stack without forking the runtime. The `infra.tsx` flow is
runnable today via the Infra-X CLI; the `dbx.tsx` flow is design-only until the
standalone `db-x` CLI lands.

Follow the [Quickstart (Docker)](./getting-started/quickstart-docker.mdx) to run
`infra.tsx` against a local Postgres, then read [Time Machine](./concepts/time-machine.mdx)
for snapshots and rollback.
